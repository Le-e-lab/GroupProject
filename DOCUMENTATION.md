# UPath - Technical Documentation

## 1. System Architecture

### Backend (Node.js + Express + Sequelize)

- Runtime: Node.js with Express.js framework.
- Database: SQLite (`timetable.sqlite` in project root) via Sequelize ORM.
- Authentication: bcrypt password hashing plus session-based auth via `sessionStorage`.
- API base: all routes served under `/api/`.

### Frontend (HTML5 + Vanilla JS)

- Styling: CSS custom properties in `css/theme.css` for a consistent design system.
- Logic: `public/js/api.js` is the centralized API wrapper.
- Libraries: `html5-qrcode` (QR scanning) and `Chart.js` (analytics charts).

---

## 2. Database Schema

- `Users`: students and lecturers (`id`, `fullName`, `role`, etc.).
- `timetable`: all 895+ class sessions with program and venue data.
- `Attendances`: attendance records (composite key includes `classId`).
- `Sessions`: active TOTP sessions generated by lecturers.

## 3. Key Workflows

### A. Lecturer - Generating an Attendance Code

1. Lecturer logs in and opens the QR Code page.
2. Lecturer selects the active class from the dropdown.
3. Lecturer clicks Generate Code, which calls `POST /api/attendance/generate-code`.
4. Server creates a TOTP session with a two-hour expiry and returns a six-digit code.
5. Code refreshes automatically every 30 seconds.

### B. Student - Marking Attendance

- Via six-digit code (`enter_code.html`): student enters the code and calls `POST /api/attendance/validate-code`.
- Via QR scan (`scan_qr.html`): student scans QR using rear camera (HTTPS or Ngrok needed on mobile).
- Both flows create an `Attendances` row with `classId`, `userId`, `date`, and `method`.

### C. Analytics

- Lecturers view per-class stats with `GET /api/attendance/stats/course/:courseId`.
- Dashboard auto-detects the current class based on timetable day and time.

### D. AI Assistant (Student, Lecturer, Admin)

1. Frontend calls `POST /api/ai/assistant`.
2. Backend validates role and prompt scope before calling Gemini.
3. Out-of-scope prompts return a safe guidance response.
4. In-scope prompts return concise, actionable responses.
5. Admin debug mode may include scopes, model config, and token usage.
6. Collaborative critique mode challenges weak ideas and suggests better alternatives.
7. If live web evidence is unavailable in context, the assistant returns a search plan instead of inventing facts.

### E. Language Preference (English/French/Portuguese)

1. App auto-detects browser language on first load.
2. User may override language in profile.
3. Preference is saved server-side and reused in AI responses.
4. Fallback language is English (`en`).

## 6. Troubleshooting

- Camera not working: use the HTTPS Ngrok URL on mobile.
- Network error on login: ensure server is running with `npm start` on port 3000.
- Invalid lecturer credentials: use ID `210153` and password `staff123`.
- Invalid student credentials: use ID `240101` and password `password123`.
- AI request returns `404 /api/ai/assistant`: restart server and confirm `server/routes/ai.js` loads.
- AI request returns `401`: user is logged out or cookie expired; log in again.
- AI says out-of-scope: ask about attendance, timetable, dashboard, map, profile, or admin tasks.
- No classes on dashboard: student `program` must match timetable `Program`.
